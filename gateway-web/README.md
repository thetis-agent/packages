# @thetis/gateway-web

The browser interface of one person: the conversation list, the transcript, the composer, the control panel, and the seam through which installed packages add to the page. It is a `service` package. `thetis serve` starts one copy inside each person's own fence. The copy listens on a unix socket, `run/web.sock` in that person's userspace, and the door on the host routes `/<person>/` to it. It holds that person's authority and nobody else's: it reaches the kernel through the fence's RPC as that person and checks the login cookie with the kernel on every request. Signing in is not here; `@thetis/gateway-login` in the system userspace exchanges a password for the cookie.

## What it provides

The manifest declares `type: "gateway"`, the label `web gateway`, a `service` whose export is `startService`, and `publish: [{ port: 8777, to: "host" }]`. There is no configuration. The person served comes from `THETIS_USER`.

### Routes

All relative to `/<user>`. Every `/api/*` and `/ext/*` route needs the cookie; a non-GET request must be same-site.

| Method and path | Effect |
|---|---|
| `GET /` | The app page. Redirects to `/login` without a valid cookie. |
| `GET /assets/<file>` | The gateway's own browser files. |
| `GET /api/me` | `{ user, role, avatar, build, prefs }`. `avatar` is the URL of the picture the person uploaded, or `null`. `build` is `{ id }`, the build id (below). `prefs` is `{ developer }`, the person's "Show developer details" switch. |
| `POST /api/me/prefs` | `{ developer: boolean }` sets that switch, kept in `prefs/<user>.json` beside the last chosen model; answers `{ developer }`. |
| `GET /api/restart` | Whether a restart of Thetis is armed, for the notice every person sees: `{ pending: { reason, by, firesInMs?, deadlineInMs? } \| null, readable }`, times in milliseconds from now. Read through the kernel's `restart.status`; a kernel that refuses it to a non-admin answers `readable: false` and `pending: null`. |
| `GET /api/me/avatar` | That picture, with the type its own bytes say it is, `no-store`; 404 when there is none. |
| `PUT /api/me/avatar` | Replaces it. The body is the file itself — raw bytes, no multipart — up to 512 KB. The type is read off the first bytes and never from `Content-Type`: PNG, JPEG, WebP and GIF, and nothing else (an SVG is a document that can carry script, so it is not on the list). Answers `{ avatar }` with a fresh `?v=`. |
| `DELETE /api/me/avatar` | Takes it off again. Removing one that is not there is not an error. |
| `GET /api/sessions`, `POST /api/sessions` | The person's conversations, newest first; create one. A new conversation starts with the model the person chose last (`prefs/<user>.json`); the answer carries it as `model`. The create may carry `{ model }`, a model picked in a `+` draft before the conversation existed: it is a choice like any other, so it becomes the person's last choice first (`""` picks the configured default and forgets the choice). |
| `GET /api/sessions/<id>` | The record with `status`, `archived`, `turn`, `usage`, `model`, `title`, `interrupted` (the kernel's, when the last turn did not finish), `resumed` (where turns resumed an interrupted one: `[{ index, why, at, turn }]`) and `stopped` (when a person stopped the last turn, or `null`). A child in `children` carries the same three. |
| `POST /api/sessions/<id>/send`, `/cancel`, `/archive`, `/model`, `/title` | Start a turn, stop it, archive or restore, choose the model, name the conversation. `send` takes `{ text }` or `{ input }`, where `input` is a runtime `TurnInput`: a user message whose `content` is an array of parts, `text` and `asset` among them. |
| `POST /api/sessions/<id>/resume` | Carries a conversation on from where it stopped: a turn with no input (`send` of `[]`), so nothing is appended and nothing the person said is sent twice. 409 `a turn is running in this conversation`, or 409 `nothing to resume: …` when the record has no `interrupted`, was not stopped by a person, and ends on a finished reply. Answers 202 like `send`. The Retry and Continue buttons, and a subagent block's Resume, use it. |
| `POST /api/media?name=<file>` | Uploads an attachment for the person: the body is the file itself, its type from `Content-Type`, at most 8 MiB. Answers the asset `{ id, mediaType, name, size }`; a message then carries an `asset` part with that `id`. |
| `GET /api/media/<id>` | Reads one of the person's own assets, inline for the image, audio and video types the transcript draws and as a download for anything else. |
| `DELETE /api/sessions/<id>` | Discards a conversation nothing was ever said in, and everything this gateway kept about it. Refuses with 409 anything with a turn, a turn in flight, or a parent (a subagent is not a conversation); 404 when it is already gone. A record with words in it is archived, never removed. |
| `GET /api/models` | `{ model, models, yours }`: the configured default model; the models the person's providers serve (`id`, `name`, `provider`, and, where the provider's catalogue gives them, `contextLength` in tokens and `pricing: { prompt, completion }` in dollars per token), cached in the gateway for a minute; and `yours: { model, recent }`, read fresh: the model a new conversation starts with (`null` for the configured default) and the last five models the person chose, newest first. |
| `GET /api/events` | The Server-Sent Events stream: every turn event of the person, opened with a snapshot of the turns in progress and the build id: `{ user, running, build }`. |

| `GET /api/panel`, `GET` and `POST /api/packages`, `DELETE /api/packages/<name>` (`?files=1` deletes the directory too, `?unfork=1` puts the package this fork was copied from back in its place) | The built-in Extensions section of the control panel (its id stays `packages`). The page uses the list, the install and the plain removal; the other two stay for API callers. |
| `GET /api/ui` | What installed packages add to the page, for the person's role. |
| `GET /ext/<scope>/<name>/<path>` | A browser file of an installed package, from under its declared `dir`. |
| `POST /api/ext/<scope>/<name>/<verb>` | A command an installed package declared. Body `{ session?, args? }`. |
| `GET /api/ext/<scope>/<name>/<verb>/stream?args=<json>&session=<id>` | A verb declared with `stream: true`, as Server-Sent Events: each value the export yields as `item`, then `end`, or `error`. |
| `GET` and `PUT /api/ext/<scope>/<name>/<verb>/raw?args=<json>&session=<id>` | A verb declared with `kind: "raw"`: bytes rather than JSON. `GET` serves what the export answers (its status and headers, always under `Cache-Control: no-store` and `Content-Security-Policy: default-src 'none'; sandbox`, a stream piped as it comes); `PUT` carries the body whole, at most the command's `maxBytes` (413 `That upload is larger than N KB.` past it), and answers `{ data }`. `args` is a JSON object of at most 4096 characters, as for a stream. |
| `POST /api/ext/<scope>/<name>/<verb>/frame` | Mints a token for a verb declared with `kind: "frame"`. Body `{ args }`, the same checks as a command's (no session), answers `201 { token, base }` where `base` is `f/<token>/`. A token names this person, that verb and those arguments, for twelve hours; a person holds at most 64, the oldest going first. |
| `GET /f/<token>/<path…>` | **No cookie.** The one route whose credential is in the URL: a document served into a sandboxed iframe has an opaque origin and sends no `SameSite=Strict` cookie for anything it loads, so the token stands for it. The frame export is called as `(args, env, { path })` with the minted arguments and the minting person's environment, `path` relative and plain (no dot-files, no `..`, at most sixteen segments; `""` for the root). The answer is checked like a raw one, its type must be one a frame may carry (html, plain text, css, js, json, svg, png, jpeg, webp, gif, woff, woff2, ttf, otf, mp4, webm, mp3; 502 otherwise), and it goes out under the frame policy: `sandbox allow-scripts; default-src 'none'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; font-src 'self' data: https://fonts.gstatic.com; img-src 'self' data: blob:; media-src 'self'; connect-src 'none'; frame-src 'none'; form-action 'none'; base-uri 'none'; frame-ancestors 'self'`, with `Cache-Control: private, no-store` and `Referrer-Policy: no-referrer` (and no resource policy: the sandboxed document's origin is opaque, which no site matches, so `same-site` would refuse its own pictures). Unknown, malformed or expired token, or a path no document asks for: 404. |

Every route matches its own path and nothing beneath it. A predicate that reads one segment matches everything below it too, and `GET /api/me` came within a length check of answering identity for `GET /api/me/avatar`, so each one pins its segment count and anything deeper is a 404.

JSON request bodies and stored gateway state are validated with Zod. Arrays, primitives, and incorrectly typed model, title, or archive fields receive HTTP 400. Invalid stored records name the offending field; legacy state is fully validated before migration writes any files. Unknown stored fields survive updates.

### The `thetis.ui` contract

A package declares `ui` inside the `thetis` field of its manifest. The kernel never reads the field. The gateway reads it from `kernel.packages.list()` on each request and does four things:

- serves the package's browser files at `ext/<package>/…`, only from under the declared `dir`, and only `.js`, `.css`, `.svg`, `.json` and `.md`;
- composes `api/ui`: one entry per package with a valid declaration, in install order, with the entries and verbs above the person's role left out and the hidden entries named;
- has the page import the declared `entry` and call its default export, `install(ext)`;
- forwards a declared verb to the named export of the package's `main`, after checking that the package declares the verb, that the person's role clears the command's `role`, and that `session`, when named, is one of the person's own. The export runs inside the person's fence as `(args, env)`, where `env` is the fence environment plus `user`, `role` and `session`. A string answer becomes `{ text }`, an object `{ text?, data? }`, and no answer becomes `{}`. A thrown error returns `400 { error }`; a malformed answer or data that cannot be serialized returns 502.

A command is one of four kinds, and each has its own route; a verb reached through the wrong one is refused with a sentence naming the right one. `stream: true` makes it a subscription (`/stream`). `kind: "raw"` (default `"json"`) makes it carry bytes (`/raw`): a download, an upload, a picture for an `img`. A raw export is called as `(args, env, { method, body? })`. On `GET` it answers `{ status?, headers, body }` — `status` defaults to 200, `headers` is a plain object (names are lowercased; `set-cookie`, `cache-control` and `content-security-policy` are dropped, because the gateway sets its own), `body` a `Readable`, a `Buffer` or a string. A stream has no size cap and no timeout, and `env.signal` is aborted when the browser lets go, so an export that reads a file or writes a zip stops when nobody is listening. On `PUT` it receives the body as a `Buffer` (`maxBytes` at most: a positive whole number of bytes up to 512 MiB, default 1 MiB, allowed on raw commands only), the 30 s command timeout applies, and whatever it returns is answered as `{ data }`, bounded like a command's answer (finite numbers, 256 KiB). A raw command cannot also stream. The page lists these verbs under `raw` in `api/ui`, beside `commands` and `streams`.

`kind: "frame"` makes a verb serve documents into a sandboxed iframe (the `/frame` mint and the `f/<token>/` route above). A frame export is called as `(args, env, { path })` and answers what a raw `GET` answers, for the document at the root (`path` `""`) and for every file the document names by a relative path (`assets/hero.png`), which the browser fetches under the same token. It is the way a package shows HTML it did not write — an artboard the model made, say — with its scripts and inline styles running and nothing of this origin in reach: the document has no cookie, no access to the page, and may not fetch or submit anywhere. A frame command cannot stream and takes no `maxBytes`. The page lists these verbs under `frames`.

Every message a frame posts to the page is untrusted input: the document's own scripts share its window with whatever runtime the package put there. The shell delivers only messages from that iframe's window carrying the nonce it was mounted with, and a package still validates the shape of what arrives, clamps its numbers, and never treats a message as authority to change anything but the one thing the frame was minted for.

A bad declaration refuses that package by name; the rest still composes. A `dock`, `places`, `sidebar`, `chips`, `composer`, `shelf`, `statusbar` or `tabs` id belongs to the first installed package that declares it. Panel ids are namespaced by package.

A `sidebar` entry says where it goes with `slot`: `head` (the default) is the strip under the brand, where a package mounts one thing (the project switcher); `section` is a collapsible list above the conversations (the canvases), with the shell's chrome — a heading that folds and is remembered, a count, a strip for the package's own actions — around a body the package draws. The module's `mount(body, { setCount(n), setActions(...nodes), expand(open?) })` gets the body and those tools; a head mount gets only its node, as before.

A `tabs` entry declares a kind of tab a package opens beside the conversations, by id (`{ "id": "canvas", "label": "Canvas", "icon": "M…" }`). The module registers it with `ext.tab("canvas", { open })`, where `open(root, handle)` draws the whole pane into `root` and answers `{ unmount?, activate?, deactivate? }` (or the unmount function alone); `handle` is `{ id, kind, params, setTitle(text), setNote(text), close() }`. The shell draws the tab (its declared icon and label, the title the package sets) and no chat bar: the package owns its toolbar. While such a tab is on screen no conversation is — `ext.conversation.current` is `null`, as in a `+` draft — the composer is hidden, and the address bar names the tab as `#<kind>/<id>`, so a refresh comes back to it. A kind declared but not yet registered shows "Loading…" until its module lands.

A minimal manifest, from `@thetis/ui-context`:

```json
"thetis": {
  "type": "ui",
  "ui": {
    "dir": "ui",
    "entry": "index.js",
    "style": "index.css",
    "dock": [
      { "id": "context", "label": "Context", "icon": "M7.5 4 3.5 10l4 6 M12.5 4l4 6-4 6", "hint": "What the model received on the last call", "wide": true }
    ],
    "commands": [ { "verb": "context", "export": "uiContext" } ]
  }
}
```

A minimal `ui/index.js`, from `@thetis/ui-marketplace`:

```js
import { openGallery } from "./gallery.js";
import { openPage } from "./page.js";

export default function install(ext) {
  ext.place("marketplace", {
    open: (root, params) => (typeof params?.name === "string" && params.name ? openPage(ext, root, params) : openGallery(ext, root)),
  });
}
```

The panel's navigation is a tree view (`assets/lib/tree.js`: `role="tree"`, disclosure toggles, nesting to any depth, the arrow keys, what is open remembered in `localStorage`). A `panel` entry declared with `under` (a built-in section id such as `packages`, or `<package>#<id>`) is not a node of its own: its module registers `{ mount, children }`, the tree hangs what `children()` answers (`[{ id, label, note?, mark?, look?, closed?, children? }]`, `mark` being `err`, `warn` or `dim` for a dot, `look: true` saying the node needs a look whatever its dot's tone, `closed: true` starting a parent closed until the reader opens it, `children` nesting further) beneath that section, and selecting one mounts the entry with `{ child, refresh }` in the second argument, `refresh()` asking the tree to read the children again. `@thetis/ui-admin` hangs one page per configured package under Extensions this way. A child may carry `marks`, a list of `{ glyph, tone, title }` drawn after its label as small squares with the sentence as the tooltip (`tone` warn, err, accent or ok); a node with a warn or err mark, or with `look`, needs a look, and the section shows how many of the nodes below it do, at any depth, pages apart ("4 need a look", in the page's font, and nothing when none does: every hung page can be opened, so a total would say nothing). `@thetis/ui-admin` marks each extension family the Extensions place has a to-do for, so the count is the place's attention count, and hangs Thetis's own parts under one closed "Part of Thetis" node. On a phone (under 600px) the tree gives way to one select of the same nodes, indented by depth, because a tree in a box of its own hid most sections behind an inner scroll. `kind: "page"` names a child that is a page rather than a package, drawn in the sans face. The nav's foot lists the glyphs in use and offers "only what needs a look", which hides the children without one, remembered with the tree state. The mount's second argument also carries `open(child)`, so a page can send the reader to a sibling page.

`ext` is bound to the one package. It offers a registration function per slot (`dock`, `panel`, `place`, `sidebar`, `chip`, `composer`, `shelf`, `statusbar`, `tab`), `transcript` for a renderer, `request(verb, { session, args })` for the package's own verbs, `open.dock|place|shelf|panel(id, params?)` (a package's own entry first; else the one entry of that id another package declared, so `ext.open.place("marketplace", { name })` reaches the Extensions place from any package; or a full `<package>#<id>` key), `open.tab(kind, id, params?)` and `close.tab(kind, id)` for a tab of a declared kind (resolved the same way, so any package can open a canvas by its id), `subscribe(verb, { args, session, onEvent, onClose })` for the ones it declared with `stream: true` (it returns the stop function), `can(verb)` for whether a verb of any kind is declared and cleared, and the shell's `dom`, `ui`, `markdown`, `conversation`, `events`, `redraw` and `open`. `markdown(text, { image })` renders `![alt](src)` as an `<img>` for an `https:` source; a relative source is passed to `image(src)`, which answers a URL (a `data:` URL, as the marketplace page does) or `null`, in which case the alt text is shown. `conversation.current` is `null` when no conversation is on screen: a `+` draft, or a tab of a package's kind.

`ext.raw` exists only when the package declared at least one `kind: "raw"` command, so a module written for this gateway must guard `ext.raw?.url` and say so when it is missing. `raw.url(verb, args, { session }?)` answers the relative route (`api/ext/<package>/<verb>/raw?args=…`) for a `fetch`, an `img`, an `object` or `location.assign` — the browser handles a `content-disposition: attachment` as a download. `raw.put(verb, args, blob, { onProgress, signal, session }?)` sends a `File` or `Blob` as the whole body and resolves with the parsed reply (`{ data }`); it is an `XMLHttpRequest`, because `fetch` has no upload progress, and `onProgress({ loaded, total })` follows the bytes up. A refusal rejects with an `Error` carrying the server's sentence (and `status`); an aborted `signal` rejects with an `AbortError`.

`ext.frame` exists only when the package declared a `kind: "frame"` command, guarded the same way. `frame.url(verb, args)` mints a token and answers the relative base its files are under, `f/<token>/`. `frame.mount(verb, args, { path, title, className, onMessage, onReady })` mints and builds the iframe itself — `sandbox="allow-scripts"` and nothing more, `referrerpolicy="no-referrer"`, its `src` the path under that base with a version and a nonce in the fragment — and answers `{ node, base, nonce, post(data), reload(path?), destroy() }`. The frame's origin reads as `null`, so `postMessage` cannot check origins: the shell delivers to `onMessage(data)` only a message from that iframe's own window carrying the nonce (stripped on the way in), and `post` sends with the nonce and `targetOrigin "*"`. A document that posts `{ type: "ready" }` on load makes `onReady(true)`; none within ten seconds, or an iframe error, makes `onReady(false)`, which is how a package learns its token expired (mint again). `reload()` changes the version in the URL, so a file changed under the same name is fetched again. A package with many frames under one token may use `url` alone and build its own iframes, keeping the same rules.

Five more members serve the page's life across updates and restarts, and are the one implementation every package uses:

- `ext.notice(id, { title, body?, tone?, actions?, progress?, dismissible?, onDismiss? })` shows a persistent card in the bottom-right corner, above the toasts, and answers `{ update(partial), close() }`; `ext.notice.close(id)` closes it. One card per id, replaced in place (a countdown or a progress sequence is one card that changes). The id is the package's own: the gateway prefixes it with the package name, so two packages cannot replace each other's cards. `tone` is `info` (default), `warn`, `error` or `ok`; `body` is a string or a Node; `actions` are `[{ label, run, primary? }]`, each button disabled while its `run` promise is pending; `progress` is `{ steps: string[], at: number, failed?: boolean }`, drawn as a list with the steps before `at` done and `at` current (or failed); `dismissible` defaults to true and `onDismiss()` runs when the person closes it. An `update` to a card the person dismissed is dropped. DOM: `.corner > .notice-host > .notice.is-<tone>[data-notice="<package>:<id>"]` with `.notice-title`, `.notice-body`, `.notice-steps > .notice-step.is-(done|now|later|failed)`, `.notice-actions > .notice-action(.is-primary)` and `.notice-x`.
- `ext.awaitReturn({ timeoutMs = 90000, onState?, since? })` answers `"back"` once the connection to Thetis went away and came back (or only came back, when it was already away), else `"timeout"`. `onState(state)` hears `waiting`, `gone`, then `back` or `timeout`. "Back" is the page's event stream opening again: the gateway answered, so its fence and Thetis are up. `since` (epoch ms) answers `"back"` at once when the connection already came back after that moment, for a caller whose restart request may have outlived the restart. While a wait is pending the reconnect loop retries every two seconds.
- `ext.developer()` is the person's "Show developer details" switch (the footer's **Developer details** button, kept per person by the gateway), and `ext.onDeveloper(fn)` calls `fn(on)` when it changes and answers the stop function. Raw dumps, problem lists and internal rows are shown only while it is on.
- `ext.turns.running()` says whether any of the person's turns runs, subagents included; `ext.turns.onIdle(fn)` calls `fn()` each time that set becomes empty (not at once when it is already empty) and answers the stop function.
- `ext.build` is `{ id }`, the build the page was loaded with. The page itself refreshes on a changed build (below); a package need not.

`ext.ui.menu(at, items, { onClose }?)` is the shell's floating menu (`assets/lib/menu.js`), the same rows as the ≡ menu in the sidebar head, appended to the body and kept inside the viewport: `at` is an element (the menu opens below it, or above it when the bottom of the window is in the way) or `{ x, y }` (a right-click). `items` are `{ label, icon?, key?, hint?, danger?, disabled?, run }` or `"-"` for a rule; `icon` is a path or list of paths for `dom.icon`, `key` the shortcut shown after the label. It answers the close function; `onClose()` runs once, however the menu went. Arrow keys wrap over the enabled rows, Home and End reach the ends, Enter or Space chooses, Escape closes (stopped on the capture phase, so the place under it stays), and so does a click elsewhere. One menu at a time: opening another closes the first. The DOM is `div.menu.is-floating[role=menu] > button.menu-item[role=menuitem]` (`.is-danger`, `[disabled]`) `> span.menu-icon + span.menu-text > span.menu-label + span.menu-key`, and `div.menu-sep` for a rule. A menu none of whose items has an icon has no `span.menu-icon` column at all, so no empty gutter sits before the labels.

A transcript renderer (`ext.transcript(render)`) is offered every tool event, and, once a message bubble is complete, `{ type: "message.rendered", role, session, node, restored }`: `node` is the bubble's `.msg-text`, `role` is `user` or `assistant`, `restored` says the bubble was built from the saved record rather than settled live. A restored bubble is offered as it is built; a live one when it settles — the `message` event, or the tool call that ends its text. The answer is ignored: a renderer decorates the text in place (linking paths, say) and never replaces the row. A subagent's nested transcript offers its bubbles too, under the child's session id.

Two more kinds reach a renderer, both message-level (a Node answered is placed as its own row and ends any tool run): a live `extension` event as the turn emitted it, `{ type: "extension", name, data }`, so a package draws its own events (a compaction's card, say) and one nobody takes is ignored as before; and, while a record is restored, `{ type: "marker", index, session, record }` before the saved message at `index` and once more with `index` equal to the conversation's length after the last, so a package can draw what belongs between messages rather than to one (the same card at the compaction's cut, read from `record.harness`). Markers are offered only when at least one renderer is registered, and only by the top-level transcript; a nested one offers nothing to renderers.

## Use

A person opens `/login`, signs in, and lands on `/<person>/`. The sidebar lists their conversations grouped by day, with a search box and a `+` button. The ≡ menu in its head opens the places, each with its one-line hint shown whole, in the order a person reaches for them: **Files** (`@thetis/ui-workspace`), **Extensions** (`@thetis/ui-marketplace`), **Workflows**, **Project** (`@thetis/projects`), then any other place a package adds by its declared order, and the **Control panel** last (`menuOrder` in `views/menu.js`; the place ids come from the packages' declarations). Choosing one closes the sidebar drawer on a narrow screen, so the place is never left under it. The footer shows who is signed in and **Log out**; clicking the face there chooses an image from the machine — the page shrinks anything larger than 256 pixels before it sends — and the × beside it goes back to the initials. The composer sends on Enter; the model pill chooses a model per conversation. Its list (`lib/model-choices.js`) reads in the order a person looks: **This chat** (the model that answers here), **Your default** (what a new chat really starts with — the model chosen last, or the configured one when the person never chose — and, when those differ, "Thetis default · …", which picks the configured model and forgets the choice), **Recent** (the last five chosen, newest first, without the ones above), then **All models (N)** folded until opened or filtered, each row with its price per million tokens read and written and its context size where the provider's catalogue gives them. The filter looks through every row and lists each model once. Any choice becomes the next default, as it always did; the toast says so. A `+` draft shows the pill too: a pick there is held until the first message and travels with the create. A new chat, before anything is said, shows one line on what Thetis does and three example prompts; a click puts one in the box and sends nothing. A picture pasted into the box, dropped anywhere on the conversation, or picked with the paper-clip is uploaded at once and shows as a chip in a tray above the box — a thumbnail, its name, and its size once it has landed, or the reason it did not with a Retry — and goes with the message as an `asset` part; a picture alone is a message. The tray takes PNG, JPEG, WebP and GIF, and the PDF, audio and video kinds the shipped adapters translate, up to 8 MiB and ten to a message; anything else is refused with a toast. A send waits for an upload still on its way, and a refused send puts the text and the attachments back. The transcript streams the reply, shows a reasoning model's thinking in a fold above it that closes when the answer starts, folds tool calls into runs, and puts a footnote with the model, cache share, tokens and cost under each reply. A tool call that goes quiet turns amber with a line saying how long it has been silent and that the model is being asked whether to keep waiting, and then says what was decided and by whom: a continue goes back to running and greys the line, a cancel turns the card's badge to `cancelled` and the line red. Amber is deliberate and so is the stopped pulse: the work is still running, nothing has failed, and a stall that reads as a hang is exactly what this is for. The sidebar row and the tab say the same thing in three words (`shell · quiet`, `Waiting on the model`), so a conversation that is not open still shows it. The thinking is live only: nothing saves it, so a reload shows the conversation without it. The rail holds one button per registered dock, each named by its label (`aria-label`) with "label — hint" as its tooltip; the ⇆ at its foot widens it to show the labels in words, remembered on this screen. The header chips each say what they are on hover ("Cost of this chat", the model with "Click to change it", a package chip's own sentence or else its declared hint). The "Latest" pill leaves room under the last row while it shows, so it never covers the last tool group. The control panel takes over the main pane; its close button returns to the conversation. Its tree is set in the page's own font at every depth. A place opened as `ext.open.place("panel", { section, child, tab, layer })` hands `tab` and `layer` to that first page, so another surface can open an extension's Settings at everyone's layer (`layer: ""`) or a person's. Escape closes the top layer and only that one (`lib/layers.js`): the drawer before the place under it, the dock when nothing is over it, and never anything while a menu, a picker's list or a popover is open — those take Escape for themselves. It never closes a place: a place is somewhere a person went, and one Escape too many (after a menu or a confirm had closed, or in a search box) used to throw away the whole page; its ✕ and the menu leave it. Its Extensions section is built in and small (below); every other section, dock, place and chip comes from an installed package.

On a phone (under 600px) the rail is not a column: a **Panels** button at the end of the tab strip lists the docks as a menu, and a dock opens over the whole screen. The control panel's tree is a select. Long pills wrap and tables scroll inside their own box, so the page never scrolls sideways, and the shelf takes at most two fifths of the height, whatever height was remembered on a larger window.

A refresh comes back to the conversation that was on screen. The address bar names it — `/<person>/#<session id>` — and that one id is the whole of what the page stores to find its way back: it is a fact about the page rather than a preference about it, it is visible where it is kept, each browser window keeps its own, and the link it makes opens the same conversation for anyone who can read it. The tabs are not restored, only the conversation being read. A hash naming a conversation that no longer exists falls back to the newest one, and one naming an archived conversation opens it, because coming back to where you were is not a judgement about which conversations are interesting. Archiving a conversation that is open in a tab closes that tab: putting a conversation away and still sitting in it is two answers to one question. The neighbouring tab takes over, the archive bucket in the sidebar opens, and the toast's Undo brings the tab back as well as the row. The conversation comes back whole whether or not a turn is running in it: `GET /api/sessions/<id>` carries the saved messages and, separately, the turn the hub is carrying, and the page draws the record and then replays that turn's events on top. The kernel writes a turn's input into the saved conversation the moment the turn starts, so the record holds that one message twice — in `conversation` and as `turn.input` — and the transcript draws `turn.input` only when the conversation does not already end with it.

The address bar is also a way in. Changing the hash of an open page to another `#s_…` switches to that conversation, and a subagent's id opens the subagent in its own read-only tab, its parent read from its record; an id that names nothing here says so in a toast. A package's tab is named the same way, `#<kind>/<id>` (`#canvas/c_1a2b3c4d`): the page waits for the extensions to load, then opens it, and a kind no package here declares says so in a toast and falls back to the newest conversation. `+` does not create a conversation: it clears the pane to "No messages yet" and the first message sent creates it, so a `+` nobody types into leaves nothing behind. (The model pill shows there too: the new conversation starts with the model chosen last, or with the one picked in the draft, which travels with the create.)

A turn that did not finish leaves one row in the transcript, and it stays there after a refresh. It says why in one plain sentence — "The connection to the model kept dropping (6 tries), so the reply stopped here. Everything before it is kept." — with the raw words under **Details**, and carries one button: **Retry** after a failure, **Continue** after a Stop. Both post `resume`, which runs a turn with no input over the saved conversation, so nothing is sent twice. Live, the row is drawn from the turn's `error` event (its `kind`: connection, rate limit, overloaded, timeout, credits, context, output limit, content filter, key; or its `why`: restart, update, crash); on a reload, from the record's `interrupted` when no turn runs, or, for a Stop, from the gateway's own `stopped` mark or a cut reply. A reply that stopped part-way (`@thetis/harness-core`'s `partial` mark) is drawn dimmed with a **cut off** tag, live as soon as the turn's `error` arrives as well as on a reload, and a tool result for a call that never ran (`notRun`) reads `not run` rather than failed. While a turn with no input runs, the cut reply it carries on from is taken off the page, since the resume drops it. When the resume starts, the row goes (a subagent's nested row too): the divider says what happened, as a reopened transcript shows it, where the resume has cleared `interrupted`. After a turn with new input, the row stays without its button. A turn that resumed an interrupted one draws a thin divider — "Resumed after Thetis restarted", "Resumed after an update", "Retried" — and the gateway keeps where it began (`resumed`, at most 50 per conversation), so a reopened transcript draws it in the same place.

While @thetis/harness-core retries a round by itself it sends `harness-core.retry` events, and the transcript shows one amber row: "The connection to the model dropped. Retrying in 8 s (2 of 6)." with **Retry now** (the harness-core UI command `retry-now`) and **Stop**. The count is of calls, the first one included: `retryAttempts` 5 is six calls, and the failure row after them says "(6 tries)". The half-drawn round — its bubble, its thinking, its half-written tool call — is taken off the page on `waiting`, because it is being thrown away. The row settles into "Reconnected after 1 retry." on `recovered`, and becomes the failure row when the retries run out. A round that reconnects and then drops again (a stream cut part-way on every attempt sends `recovered` on each attempt's first words) stays one row: the next `waiting` takes the quiet row's place. The sidebar says "Reconnecting — attempt 2 of 5" meanwhile. A tool call whose arguments are still streaming (the provider's `tool_call.progress`) shows as a card reading "writing write_path… 31k chars" until the call itself arrives. A subagent whose turn failed shows the reason in a few words beside its **failed** badge, and a **Resume** button that resumes the child; a `resume_subagent` call by the parent draws into the same block.

The page survives a restart. The event stream is reopened by the page itself — after one second, then two, four, up to fifteen, "Reconnecting…" in the footer — because a 502 from the door while Thetis restarts closes a browser `EventSource` for good. `/api/me` and each stream's snapshot carry a build id (a hash of this package's version, the modification times of its browser files, the versions of installed packages that add browser files, and the runtime's commit when its `.git` can be read); when a later one differs, the page is running old code and refreshes itself on the same conversation — at once when nothing is typed and no place is open, else through a notice, "Thetis was updated · Refresh". What is typed in the composer is kept in `sessionStorage` whenever the page goes away and put back when it loads, so any refresh keeps it. While a restart of Thetis is armed, everyone sees "Thetis restarts in 20 s · your reply will continue" (the second half only while a turn runs), then "Thetis is restarting" while it is away, then "Thetis is back."; the page asks `GET /api/restart` on load, at the end of each of the person's turns, every ten seconds while one is armed or one of the person's replies runs, and every minute otherwise. A reply running is when a restart matters, since it pauses that reply; asked once a minute, a restart armed during a long tool call was first shown after the reply had already paused.

The toasts and the notices share the corner: notices on top, toasts under them. On a phone (under 600px), while a field has the focus, the corner moves to the top of the screen, so a toast never covers the field being edited or sits under the keyboard (`lib/toast.js`, `.corner.is-top`). Usage is kept for a turn that failed or was stopped too; each reply's usage is paired with the saved message that says the same thing, so a cut reply is passed over rather than given another's cost.

A conversation nothing was ever said in does not stay. It is not a record of anything — it is the click that made it — and a column of "New conversation" rows is something to read past to reach the one that matters. The page discards them in the two places it can be sure of: when their tab is closed here, which is a person leaving a conversation, said plainly and in time to act on; and on the next load, which sweeps whatever it never got to see closed, because a browser tab shut or a machine that died tells this page nothing. Deliberately not on `beforeunload` or `pagehide`: a request started there is not reliably sent, so the sweep would still be needed, and those events fire on the way into the back/forward cache as well, which is not leaving at all — the person presses Back and finds the conversation they were in gone. An empty conversation harms nothing until it clutters a list, and a list is only read on a load, so catching what can be caught honestly and sweeping the rest is the whole design.

The guardrails sit on both sides of that. `DELETE /api/sessions/<id>` is the floor and it checks the record rather than the page's word for it, because the list a page holds is always a moment old: anything with a turn in it, a turn in flight, or a parent is refused. The page is narrower again — it leaves alone one that was named or archived, one open in a tab here, the one being read, and any conversation made in the last two minutes, since that one is very likely being typed into in another window right now. The sweep runs after the conversation the address bar names is open, so it cannot take the one the page just came back to. And nothing about this is ever shown: it is tidying nobody asked for, so a refusal is an answer and not a fault, and 409 is the ordinary way the server says "somebody got there first".

The built-in Extensions section of the control panel (`assets/views/panel-packages.js`, id `packages`) lists what is installed. Adding, updating, setting up and removing extensions, a copy of one and the way back to the official version, and what everyone gets all live in the Extensions place of `@thetis/ui-marketplace`. When that place is here — declared by that package or a copy of it, and loaded — the section lists every extension installed for this person, each row opening that extension's page there, and offers **Manage extensions**, which opens the place itself. When it is not, a person must still be able to install from the browser, so the section offers **Install from a source**, the list of what is installed, and **Remove** on each row — never on an extension Required by Thetis (the gateways, providers, storage and host packages, the harness, the marketplace and its place, the control panel and the sign-in page), whose row says "Required by Thetis" instead; the Remove confirm says "Your saved settings are kept."

Both lists use the columns every extension list uses (the Extensions contract, the same as ui-admin's All extensions): **Extension** — the label in Title Case, the raw id as its tooltip, and the publisher line under it (`by Thetis`, `by you`, `by <person>`, then what it brings: Tools, Skills, Page, Models, Background, the first two) — **Status**, at most two chips from Needs setup, Update available, Customized and For everyone, each with its tooltip, **Version** and **What it does**, sorted by label; the heading's count is what is installed for this person, the number the place and All extensions give too. A missing setting that only an admin can set (a `${VAR}` the server's environment lacks, a system-scoped key) is Needs setup for an admin and the grey line "Waiting for your admin to finish setting this up" for anyone else. One verdict everywhere: when the Extensions place is here, the section reads the place's own rows (its `search` command with `folder: true`) and judges them with the place's own rules — its browser module `state.js`, byte-identical to its `lib/state.js`, imported from where the place's UI is served — with this person's own settings folded on from `/api/packages` (`withSetup`: a broken report's summary and missing keys, so Needs setup is the place's) — so the labels, publisher lines (a shared copy finds the person whose original it was made from: "by bitmuse"), chips, sentences, What it does (the place's `summaryOf`, the manifest's plain `thetis.summary` first) and the count ("16 installed · 20 part of Thetis", the place's own two numbers) are the place's and nothing is restated. The list is the place's Installed cards; Thetis's own parts are folded beneath it under "Part of Thetis (N)". A customised copy whose official version moved on is Customized, never Update available. Without the place (the bootstrap), a short fallback (`FALLBACK`: `stateOf`, `publisherLine`, `labelOf`, `typeOf`, `isRequired`, `CHIPS`) says the chips, the label, the publisher line and Required plainly; `test/panel-packages.test.js` holds the fallback to the place's chips over the same rows, and the place-backed path to the place's exact answers and count. On a phone the What it does column is left out; each extension's page says it.

`src/panel.ts` serves the rows out of `kernel.packages.list()` and imports no domain package, so the section works with nothing else installed. A row carries the name, version, type, description, the manifest's `label`, `scope` and `everyone`, `everyoneBy` (config, promoted or marked), `audience`, `source` (system, local or git), `steps`, `tools`, `service`, `hasSkills`, `pages`, a fork's `forkedFrom` and `fork` (the origin's version on disk now and whether the copy differs), `replaced`, `loaded` (the version this person's workspace loaded, when it is not the one on disk), and, for an extension that declares settings and is missing one at this person's layer, `config: { broken, summary, keys }` from `kernel.config.show`, the missing keys with their scope, the environment variables they lack, their source and help, never a value.
