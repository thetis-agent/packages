# @thetis/ui-admin

The web gateway's control panel beyond Extensions (the shell's own section), the admin's update notice, and the commands behind them: Overview, Agent, People, Models, Access (mounts and SSH keys), Activity, Account and Advanced, plus one page per extension under Extensions. It is a `ui` package with no build step and no dependencies. Its browser modules run in the page; its commands run inside the signed-in person's own fence, where `@thetis/gateway-web` calls them as that person, and most are one call over the kernel's operator channel. Every person gets the package by default. A user sees four sections, each about themselves: the models their space can call, their own mounts and SSH keys (Access), the journal rows about them, and their account and password. An admin sees all of them, about everyone. `api/ui` drops the entries and verbs above the person's role, and the kernel answers a user's fence only about that user.

Every sentence that names the agent or the server ("Restart Thetis", "Part of Thetis", "by Thetis") says the name an admin gave it on the Agent page: the entry calls `useAgentName(() => ext.agent?.name || "Thetis")` from `ui/state.js`, and each module reads `agentName()` when it draws. The server-side commands have no name to read and keep Thetis.

What people read follows three rules. **Errors never look like empty data**: a section whose command failed says "Mounts could not be read: <plain reason>. <what fixes it>", with **Restart Thetis** for an admin when only a restart fixes it (a host package the server holds an old copy of) and the raw error folded under Details, never "0 mounts" or "No person has a workspace here"; no raw module error reaches a toast. **Three words for new code**: a copy is **Up to date**, **Update ready** (its workspace has not applied the copy on disk, or a registry holds a newer one) or, for the Thetis server alone, **Restart needed**; the server works the word out and the page draws it, so there is no "older code", no `reload to X` and no glyph legend. **Plain words**: fence, userspace, daemon, reload, fork and promote do not appear; admin pages say "workspace", a person's own views say "your space", a package is an "extension", a fork is "your copy", promote is "Share with everyone…". The CLI commands quoted for the host keep their own words. **One state per extension** (the Extensions contract): every extension surface here — the tree under Extensions, All extensions, Who has what, an extension's page — says the same thing the Extensions place says about the same extension: its label in Title Case (the raw id only as a tooltip and in the technical cards), the publisher line (`by Thetis`, `by you`, `by <person>`, `from <registry>`, then what it brings: Tools, Skills, Page, Models, Background), at most two chips from **Needs setup**, **Update available**, **Customized** and **For everyone**, each with its tooltip, and one sentence why when it asks for attention. The rules are `@thetis/ui-marketplace`'s `lib/state.js`, copied into `ui/state.js` byte for byte and held to it by a test.

The verbs marked Anyone above carry no role; every other verb is an admin's. Each checks its arguments first, so a refusal is a plain sentence before the kernel is asked, and answers `{ data }`. The person's own id comes from `env.user`, never from the arguments. The `host.grants.*` methods are answered by `@thetis/host-grants`, a package of type `host` the host process loads; the kernel only dispatches them, so an edit to that package is live on the next call and no restart is ever needed for the mounts or the keys.

The role is checked three times: the page draws only what `api/ui` listed for the person, the gateway answers `403` to a verb above the person's role before the package's code runs, and the kernel is the authority on every operator method. From a user's fence it admits only `users.passwd` for their own id with the current password, `journal.tail` narrowed to the rows about them, `host.grants.mountsList` and the ssh exports `@thetis/host-grants` declares a person may call on themselves (with `user` pinned to the caller), and a reload of their own fence; everything else only from an admin's. The browser modules branch on `who.role` to draw a person's own view, but a user who sent another id would still be answered only about themselves.

## Use

Anyone opens **Control panel** from the sidebar's ≡ menu. An admin's tree reads **Overview, Agent, People, Extensions, Models, Access, Activity, Account, Advanced**; a user's reads **Extensions, Models, Access, Activity, Account**. (Extensions is the shell's own section, at order 10; the entries here sort around it.)

- **The Thetis update card** (`ui/update-notice.js`, admins only): a bottom-right card through `ext.notice("thetis-update")`. It reads `update-check { fetch: "stale" }` when the page loads and every 30 minutes while the page is visible. It says one of these, drawn from `describe` in `ui/update-flow.js`:
  - **Thetis update available · N changes**, with **Show changes** (the commit subjects) and one line, "Needs a restart: running replies pause at a safe point and continue after." or "No restart: only extensions changed; the workspaces apply it.", and one button, **Update and restart** (`update-apply { then: "restart" }`).
  - The same title as a calm note when the server's checkout has local changes: it is updated by hand on the host, and there is no button.
  - **Thetis's code changed · Restart to finish** when the code on disk is newer than the running server and nothing is upstream (a checkout changed by hand): **Restart** asks host-update for the restart alone (`update-restart`).
  - While the job runs, the same card shows its steps — Downloading… Installing… Building… Checking… Pausing running replies… Restarting… Back online — with **Cancel the restart** while replies are pausing (`restart-cancel`). When Thetis goes away the card waits for it with `ext.awaitReturn()` for up to 90 seconds, then says **Back online** ("Thetis is updated to fedcba9. Replies that were running continue by themselves.") with **Reload page**; the page remembers the click in `sessionStorage`, so after the page reloads itself on the new build the admin who clicked is told Back online once. An update that needed no restart reloads the admin's own workspace, and with it the page: the reloaded page asks for the job's record again (up to ten times, a second apart, while its gateway comes back) and says **Thetis is updated** ("No restart was needed: the workspaces applied it."), never Back online.
  - A failure is said with its fix: couldn't reach the update source (Try again); commits that aren't upstream (update by hand with `deploy/install.sh`); the build failed and was rolled back ("Thetis was rolled back to 8309ab0 and is running as before", Show log, Try again); it built but the check that the new version loads caught it, **The update didn't start** ("The new version failed its start-up check (@thetis/x does not load), so nothing was restarted…"); the rollback failed too (the host command, Copy command); installed but the restart was refused (the latch's own sentence, Restart); an update already running; Thetis hasn't come back after 90 s (`journalctl -u thetis-runtime -n 50`, Keep waiting). Show log opens the Overview.
  A dismissed card stays away until it means something new (other changes, a new state).
- **Overview** (`ui/overview.js`, admin, first): the **Installation** card draws the same card inline, then where the runtime checkout and its packages submodule stand (local changes are a dim note, not an alarm), the Node version, the Thetis server's word (**Up to date** or **Restart needed**), a pending restart with **Cancel**, when the remotes were last checked (and why that failed, calmly), **What the update brings** (the incoming commits, folded), **Local changes on the server** (the files, folded), and the last update's step log (its state in words: done, failed, rolled back) with the failed or running step's output. **Check for updates** reaches the remotes now. There is no Update now, Reload N workspaces or Restart the daemon: the one button does all of it on the server. The raw configuration is Advanced → Server settings.
- **People** (admin): a table of everyone with their role, status and since when. An **Add a person** form with id, role and password. Clicking a row opens a card with **Make an admin** or **Make a user**, **Suspend** or **Activate**, **Set password** and **Remove**, each behind a confirm popover. The admin's own row shows a note instead.
- **Extensions**: the shell's section, which lists the place's Installed cards for the admin with the same columns and chips, Thetis's parts folded beneath (`@thetis/gateway-web`'s `panel-packages.js`).
